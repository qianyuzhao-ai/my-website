过去一年，我把越来越多的设计工作交给 Agent：整理 Figma 稿、生成组件代码、对照设计 token 做走查。效率确实提高了，但也出现了新问题——当产出速度远超判断速度时，设计师的价值到底落在哪里？

## 先划清边界

我的做法是把流程拆成「生成」和「判断」两类。生成类的工作，比如把稿子转成代码骨架、批量替换文案，交给 Agent；判断类的工作，比如信息层级、交互节奏和细节取舍，留给自己。

> 工具负责把事情做完，设计师负责决定什么值得做。

## 一个具体的例子

首页的 Bento 卡片最初由 Agent 按 Figma 稿生成，结构正确，但移动端的阅读顺序完全照搬了桌面。下面是调整后的排序逻辑：

```ts
function mobileOrder(id) {
  const top = highlighted[id];
  return [...top, ...rest(top)];
}
```

## 我现在的流程

- 先移动端，再平板，最后桌面端
- 每一步都留下可回退的提交
- 让 Agent 解释改动，而不只是执行改动
